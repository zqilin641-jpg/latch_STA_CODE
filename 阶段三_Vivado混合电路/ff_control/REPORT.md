# 加强纯FF对照后的结论修正

2026-11-14。以缩短原纯FF输出端内部关键路径为目标，新增三个全FF重定时候选。保持原单公共MMCM、器件、35个引脚、17个IOB输出FF位置、IO延时、SLEW FAST、时钟不确定度和输出拍次。交叉时钟不确定度已对称补齐。

因此此前混合方案相对旧FF基线的7.35%优势，不能推广到更好的FF实现。相对本轮已通过的最快FF，混合方案约慢6.60%；由于该FF最高频率尚未找到，其真实差距可能更大。

三种新FF候选各经MMCM厂商模型、LOCKED等待、数据/valid/重复数据通路复位检查，4132次零错误。实际pins.tsv、output_registers.tsv与混合方案完全相同，存储时钟网为clk。原生通过点检查setup、hold、脉宽。FF为85个FF，混合为85个FF＋16个Latch；没有隐藏混合方案的存储开销。

本轮没有新增Howard求解，直接用Vivado原生STA筛选和二分，对同一个修正后的混合检查点重新扫描。混合原生边界116.742MHz与之前Howard局部模型116.645MHz的区别来自模型近似，不是另一种实现。没有上板、SDF或形式等价证明，未穷尽全部FF边界。

screen.tsv由原扫描脚本生成：ff_3_6_10行的fail_ns=8.0仅是初始扫描下界，并非实测失败点。comparison.json已明确标注lower_bound_only，并将此项改名scan_lower_limit_ns，避免误读。其他方案均保存真实screen_pass.rpt及screen_fail.rpt。

后续应把更强纯FF基线纳入每次筛选，并重新考虑Latch候选和补偿FF的位置；在未获得同条件更好结果前，不再声称当前混合方案有频率优势。
